# Стенд: v06x с приборами

Проверки (`check.sh`, `check-funcs.sh`) гоняют CO в эмуляторе
[v06x](https://github.com/svofski/vector06sdl), но не в подлинном: к нему
добавлены приборы, без которых мерить нечего. Правки лежат рядом,
[`v06x-instrumentation.patch`](v06x-instrumentation.patch), и накладываются на
клон поверх коммита `5cbd540`:

```sh
git clone https://github.com/svofski/vector06sdl tools/vector06sdl
cd tools/vector06sdl && git checkout 5cbd540
git apply ../v06x-instrumentation.patch
make -f Makefile.darwin MT= BOOST_LIBRARY_PATH=/opt/homebrew/lib \
     BOOST_LIBS="boost_program_options boost_thread boost_chrono boost_filesystem" \
     EXTRA_DEFS=-I/opt/homebrew/include
```

(Под Intel-маком и под линуксом пути к boost свои; `-mt` в именах библиотек
нынешний homebrew не ставит, отсюда `MT=`, а `boost_system` в boost 1.8x стал
заголовочным, поэтому его нет в списке.)

## Что приборы дают

| переменная | что делает |
|---|---|
| `V06X_COV_LO/HI/FILE` | карта исполнения: по байту на адрес, ненулевой — с него брали команду |
| `V06X_DATA_LO/HI/FILE` | след обращений к памяти: `r`/`w`, адрес, значение, `pc` и состояние порта 10h (`bank`) |
| `V06X_DATA_ALL` | писать каждое обращение, а не только новую пару (pc, адрес) |
| `V06X_GUARD` | охраняемые куски (`B756-BBBF,A448-A54E`): если туда зайдёт стек, в след пишется `stack_guard=адрес:pc` |
| `V06X_RAM_SAVE` | снимок памяти (64 КБ) в конце прогона |
| `V06X_EDD_SAVE` | образ квазидиска после прогона — по нему видно, что CO записал на диск |
| `V06X_LPT` | снять разряд «занят» у принтера (порт 05, разряд 0): без этого печать в CO ждёт готовности вечно и весь её путь выпадает из прогона |
| `V06X_TRACE_*` | построчный след исполнения по диапазону адресов |

Ещё одна правка -- живучесть: за краем образа дискеты подлинный v06x бросает
`std::out_of_range`, его никто не ловит, и прогон обрывается целиком, вместе со
всем, что успел намерить. Настоящий дисковод на такое отвечает ошибкой, а не
падением, поэтому чтение за краем возвращает `E5`, запись пропускается, и в
stderr идёт строка `FD1793: read outside image`. Именно она и показала, что CO,
запущенная с диска `B:`, уезжает читать несуществующую дорожку.

Кроме приборов, в клоне есть и железо, которого у подлинного v06x нет, --
**НЖМД**. Винчестер в Векторе подключён как обычный IDE: регистры ATA лежат на
портах 50h..57h, а старший байт слова данных ходит отдельным портом 58h. Это
двести строк в `src/hdd.h` и по одному `case` во вводе и выводе `src/vio.h`.
Образ задаётся ключом `--hdd` и открывается **на запись**: всё, что система на
него положит, остаётся в файле, поэтому прогон делается по копии. Без ключа
порты молчат, система решает, что винчестера нет, и ведёт себя как раньше.

Собрать образ и посмотреть, что на нём, умеет
[`tools/mkhdd.py`](mkhdd.py); раскладку винчестера разбирает и
[`tools/hdir-code.inc`](hdir-code.inc).

В карте исполнения отмечается только **первый байт команды**: операнды остаются
нулями всегда. Поэтому считать покрытие по байтам нельзя — в знаменателе будет
вдвое больше, чем вообще может быть отмечено, и полный прогон выглядит как 40%.
[`tools/covmap.py`](covmap.py) и [`tools/covruns.py`](covruns.py) считают по
командам: сколько строк листинга исполнялось хоть раз.

Последней строкой следа обращений идёт `stack_low=` — самый нижний адрес, куда
уходил стек самого CO. Обращения к стеку в след не пишутся (их слишком много),
и без этой цифры запас под стеком приходилось брать на глаз; считаются только
обращения из кода CO и не считаются пересылки, где SP работает курсором
(`03EF`, `0D7B`, `347D` и наш обмен по `A448`).

## Зачем это в репозитории

Клон эмулятора в `.gitignore`, а правки в нём — единственное, чем меряются
буферы и покрытие. Без файла с заплатой стенд не воспроизвести: свежий клон
соберётся, но проверки перестанут что-либо проверять и покажут «всё хорошо».
