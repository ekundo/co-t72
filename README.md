# CO под MDOS T-72

Файловый менеджер **CO v2.0** (Шишатский С.М., Харьков, 1993) написан под ОС **T-34**
и ни под какой другой не запускался. Здесь он доведён до работы под
[MDOS T-72](https://github.com/ImproverX/MDOS_T-72).

Состояние: CO стартует автоматически с квазидиска, рисует панели, кириллица на месте,
диск A: перечисляется полностью. Не доделано — перечисление «своего» диска (панель C:)
и строка функциональных клавиш; после отрисовки CO уходит в цикл и не реагирует на
клавиши. Подробности ниже.

## Быстрый старт

```sh
./patch-co.sh work/co/co.com work/os-t72/os-t72.edd out/
v06x --rom os-t72f.rom --edd out/co-t72.edd
```

Исходные файлы (`co.zip`, `os-t72.zip`, `t34.zip`) лежат в каталоге программ
[Базис](https://caglrc.cc/scalar/ware/791/); образ квазидиска берётся из `os-t72.zip`
как основа — в нём уже есть `OS.COM` и, главное, корректные служебные структуры.

## Что пришлось изменить в CO

Четыре изменения, каждое проверено на живой машине сравнением с эталонным поведением
под T-34.

| # | Изменение | Почему |
|---|---|---|
| 1 | `E2BD → E2ED`, 4 ссылки | CO перехватывает вектор дисковых операций БСВВ (`SHLD E213h`), ставит свой фильтр-кэш каталога по `0185` и пропускает вызовы дальше по **жёстко зашитому** адресу обработчика. У T-34 он на `E2BD`, у T-72 — на `E2ED`. Это единственный зашитый адрес БСВВ во всём CO. |
| 2 | Перекодировка заставки КОИ-7 → КОИ-8, 63 символа | CO хранит текст в КОИ-7 и переключает набор однобайтным кодом `0Eh`. У T-72 нет ни такого управляющего кода, ни шрифта КОИ-7 (на `1B 5C` у него CP866). `КОИ-8 = КОИ-7 \| 80h`. |
| 3 | `A838 → 0040`, `A83A → 0042`, 11 ссылок | Ловушка вывода CO сохраняет туда указатель стека и вектор экрана. Вызывается она **изнутри драйвера экрана T-72**, который на входе отключает банк квазидиска, — и читает не то, что писала. `SPHL` ставил мусорный стек. |
| 4 | Установка на квазидиск C: + `INITIALC.SUB` | CO рассчитан на работу с C:. При запуске с дискеты он должен сам скопировать себя туда, но эта ветка под T-72 не отрабатывает; образ собирается снаружи. `INITIALC.SUB` — autoexec МикроДОС, даёт автозапуск. |

## Инструменты

| | |
|---|---|
| `tools/dis8080.py` | Дизассемблер 8080 с рекурсивной трассировкой. Умеет брать точки входа из карты исполнения (`--cov`) — без этого статическое покрытие 31%, с ней 34% и, главное, снимается неоднозначность «код или данные». |
| `tools/cpmimg.py` | Образы дискет МикроДОС. Геометрия взята из DPB в исходниках T-72: блок 2048, 128 записей каталога, 8 системных дорожек, 16-битные указатели. |
| `tools/kdimg.py` | Образы квазидиска. Раскладка выведена из подлинного `os-t72.edd`: запись `r` → смещение `0x3EF80 - r*0x80` при `r < 32`, иначе `0x39F80 - (r-32)*0x80`; контрольная сумма — пара одинаковых байт по `0x3F000 + r*2`, сама сумма = сумма 128 байт по модулю 256. **Без верных сумм драйвер отвергает образ** («Ошибка ЕСВВ, ST=02»). |
| `tools/patchaddr.py` | Правка зашитых адресов ОС по карте `старый:новый`. |
| `tools/koi7to8.py` | Перекодировка текстовых блоков. Учитывает, что байты хранятся инвертированными (цикл печати делает `CMA`) и что аргумент escape-последовательности трогать нельзя. |
| `tools/reloc.py` | Перенос диапазона адресов. Оставлен для истории — для этой задачи не пригодился. |

## Стенд

`patches/v06x-instrumentation.diff` — инструментовка эмулятора
[v06x](https://github.com/svofski/vector06sdl), всё через переменные окружения:

| | |
|---|---|
| `V06X_TRACE_LO/HI/FILE` | трассировка по диапазону PC, с регистрами, стеком и байтами по адресу |
| `V06X_TRACE_ALL` | полная трасса вместо «первая инструкция серии» — для сравнения двух прогонов инструкция за инструкцией |
| `V06X_TRACE_ARM/DISARM` | окно трассировки между двумя адресами, чтобы выделить один вызов ОС |
| `V06X_TRACE_MAX` | ограничение размера трассы |
| `V06X_COV_LO/HI/FILE` | карта исполненных адресов |
| `V06X_DATA_LO/HI/FILE` | обращения к памяти со значением, PC и **состоянием банка** |
| `V06X_DATA_ALL` | без схлопывания повторов |
| `V06X_PORT/V06X_PORT_FILE` | записи в порт |

Сборка под macOS требует правок сверх diff'а: `-std=c++17`, `boost::asio::io_context`
вместо `io_service`, и передавать флаги через `EXTRA_DEFS`/`EXTRA_LIBS`, а не
переопределять `CXXFLAGS`/`LDFLAGS` — иначе теряются `-DHAS_IMAGE=1` и `-DUSED_XXD=1`.

Грабли: файл трассы надо закрывать через `atexit`, иначе буфер теряется и трасса пустая;
`printf` эмулятора до терминала не доходит, только `stderr`; скриптовые точки останова
v06x вешают эмуляцию (`script_attached` поднимает `script_interrupt`, и `execute_frame`
выходит до цикла инструкций); поле «адрес возврата» в трассе — это вершина стека, после
`PUSH` оно врёт.

`scripts/*.chai` — сценарии ввода для headless-прогонов. УС при старте T-72 — это Left Ctrl.

## Что осталось

После отрисовки панелей CO встаёт в цикл по адресу `DDC1`. По этому адресу в МикроДОС
лежит одиночная `STA DE60h`, зациклиться на которой нельзя, — значит исполняется не тот
код: `DDC1` внутри окна банка, и при неверном его состоянии там оказывается видеопамять.
Это пятый случай того же класса, что и правка №3.

Отдельно: установочная ветка (самокопирование с дискеты на C:) под T-72 упирается в ту же
ловушку вывода. У дискеты в DPB `CKS=32` — включён контроль смены диска по контрольным
суммам каталога, у квазидиска `CKS=0`. Обнуление `CKS` у дискеты продвигает CO дальше
(861 исполненный адрес против 684), но не до конца.

## Проверенные и отвергнутые версии

Чтобы никто не проверял заново — всё опровергнуто измерениями:

- перенос рабочей области CO из `A000-DFFF` — **невозможен**: подпрограмма отрисовки пишет
  в экранные страницы `A6, A8, AA, B0, B5, B7, B9`, а переменные лежат в `A800..A889`,
  `B672..B6AB` — страницы `A8` и `B7` общие. Экран и данные делят страницы намеренно;
- перенос экрана в плоскость 0 — плоскость занята под сохранение экрана самим CO;
- буферы DMA в окне банка — данные доходят, в буфере лежит содержимое `CO.PRM`;
- наполнение дисков, прямая запись текущего диска в `0004`, кэш каталога, перехват
  вектора, резидентный патч МикроДОС (`DF65`), контроль контрольных сумм — по каждому есть
  прогон с отключением, поведение не меняется;
- ячейки `DE80`, `DF09`, `DF14`, `DF15`, `DF16` — значения в обеих ОС одинаковы;
- состояние порта `10h` в покое — в обеих ОС `23h`.

Полезно знать: **МикроДОС в T-34 и T-72 совпадает на 94.6%** (дамп `C000-DFFF`), различия —
правки ImproverX, в том числе вставленный байт `00` в таблице командных букв `ABDEKOU`,
из-за которого код дальше сдвинут на единицу. И **выпущенный ROM T-72 собран из более новой
версии исходников, чем опубликованные**: рантайм-адреса смещены на `+0x29/0x2A`
(`E212 → E2ED` против `L_E2E4` в исходнике). Сверять исходник с живой машиной только со сдвигом.

## Предшественники

Юрий Ларин пробовал этот же порт и выложил в телеграм-канал Вектора недоделанный
дизассемблер `co_src.7z` — 8627 строк с метками и комментариями плюс `df65.asm`
(резидентный модуль, которым CO патчит МикроДОС). Его диагноз — «куча функций обращается
даже не по векторам, а напрямую в код» — подтвердился, но масштаб оказался меньше
ожидаемого: зашитый адрес БСВВ во всём CO ровно один.
