# Память CO под MDOS T-72

Карта того, где CO живёт и куда пишет. Составлена из листинга
[`co-src/co.asm`](../co-src/co.asm) — обращения посчитаны по нему — и из
измерений на стенде: слежение за записью в v06x (`V06X_DATA_LO/HI`) показывает,
какие адреса программа трогает на самом деле.

Нужна она для трёх вещей: понимать, куда можно положить свой код, не отобрать
ли память у самого CO и не наступить ли на грабли, на которые мы уже наступали.

## Общая раскладка

| область | что там | обращений в листинге |
|---|---|---|
| `0000-00FF` | страница нуля CP/M: `0005` вызов БДОС, `005C` ОКФ, `0080` буфер обмена | 45 чтений и записей |
| `0100-40FF` | сам CO: 16 КБ кода и данных | — |
| `4000-4FFF` | каталог дискеты копией в памяти: с `4000` для `B:`, с `5000` для прочих | |
| `4100-4BFF` | каталог диска с большим оглавлением (у дискеты НЖМД их 128) | |
| `5000-5FFF` | второй каталожный буфер | |
| `6000-9FFF` | буфер копирования | |
| `A000-DFFF` | окно ОЗУ: буферы CO, его переменные, тело надписи в рамке, стек | 568 обращений |
| `E000-FFFF` | МикроДОС: БДОС, БСВВ, таблица состава оборудования по `FFC9` | 68 обращений |

| `B69B` | 23 | 29 | текущая позиция в строке |

| `A853` | 18 | 14 | указатель в списке файлов |
| `B673` | 7 | 16 | буква диска активной панели |
| `A842` | 8 | 13 | начало списка файлов |
| `A849` | 9 | 3 | буква диска, каталог которого разбирается сейчас |

## Куда уехал дописанный код

Сборка добавляет свой код в хвост образа, а работает он из трёх разных мест —
и это ровно те грабли, на которые мы наступали.

| где | что там | почему там |
|---|---|---|
| `B740-BBFF` | постоянный код: надпись в рамке, выбор дискеты НЖМД, трамплины диска `D:` | под стеком, который опущен на `BC00`; места 1216 байт |
| `A448-A54F` | обмен через буфер вне окна, поиск по дискам, кодировки просмотрщика | в окне ОЗУ, куда не пишет ни просмотр, ни копирование; переносится туда при старте (`tools/winmove.py`) |
| `45A8-49CB` | пусковое: проба оборудования, проверка `CO.ZGR`, переносчик | отрабатывает до первого чтения каталога, потом это место затирается |

## Грабли

**Стек.** CO ставит его по правилам CP/M — на вершину TPA из ячейки `0006`.
T-72 сообщает там `C000`, а сама держит килобайтный буфер дисковода на `BC00`:
каждое чтение сектора затирало стек вместе с адресами возврата. Сборка опускает
стек ниже буфера.

**Каталог диска `B:`.** Копия каталога дискеты ложится с `4000` и накрывает
`4000-4FFF` целиком. Всё, что сборка оставила по адресу загрузки выше `45A8`,
этим затирается — поэтому постоянный код там жить не может, только пусковой.

**Окно `A000-DFFF` и второй квазидиск.** На время обмена с `D:` драйвер гасит
первый квазидиск вместе с окном, и буфер в окне обменивается данными с
видеопамятью: чтение оставляет буфер нетронутым и рисует сектор полосой на
экране, запись кладёт на диск экран. README самой T-72 говорит об этом прямо.
Поэтому весь дисковый обмен CO переведён на штатный буфер CP/M по `0080` с
досылкой в настоящий.

**Код в окне — можно.** Окно выключается только на время самой пересылки, а
накладки в этот момент не исполняются: они её и вызывают. Данные — нельзя.

**Свободного ОЗУ ниже `A000` нет.** `4000-5FFF` заняты каталогами, `6000-9FFF`
— буфером копирования. Под стеком остаётся два десятка байт. Незанятые куски
есть только в самом окне: `A448-A5FF`, `A9AF-AFD3`, `B056-B662` — проверено
слежением за записью на просмотре файла с прокруткой, копировании и смене
дисков.

**Буфер ПКК.** До сборки T-72 от 17.09.2026 перенаправление ввода (`<FILE.SUB`)
читало в `0DFC9h` — внутрь окна. Со второго квазидиска это писало в
видеопамять. ImproverX перенёс буфер на `0E06Dh`.
