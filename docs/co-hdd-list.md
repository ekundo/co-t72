# Список дискет НЖМД в панели

План работы. Сейчас «СС»-«7» спрашивает номер дискеты шестнадцатеричными
знаками — ровно как команда ОС «9». Номер надо знать наизусть: что на какой
дискете лежит, нигде не видно, а метку, которую показывает рамка панели, можно
только прочитать, но не поставить (её вешает `HDIR /M`, отдельная программа из
командной строки).

Делаем так: «СС»-«7» открывает в панели список дискет, ВК на строке назначает
выбранную на диск панели, «6» вешает метку. Прежний ввод номера остаётся на
«УС»-«СС»-«7» — на случай, если винчестер отвечает ошибкой и список не
построить.

## Как это выглядит

Список занимает одну панель — ту, что активна, — и оставляет соседнюю в покое.
Двадцать строк, поле строки 39 знаков; ровно так же ведёт себя просмотр архива.
Верхняя строка панели («Диск X Файлов NN Свободно NNN Кб.») подменяется шапкой
списка, как её подменяет архив.

```
 FF ЭТИКЕТКА ДО ДВАДЦАТИ ДВУХ ЗНАК  128 780Кб
 ^^ ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^  ^^^ ^^^^^
 |  метка, подрезанная до поля       |   занято
 номер, 16-ричный                    файлов
```

Поле номера считается по числу дискет: пока их меньше `100`, хватает двух
знаков, и метке достаётся больше. Метку, которая не влезла, подрезаем и
кончаем её тремя точками. Полная метка видна в шапке — для той дискеты, на
которой стоит курсор.

Пустые дискеты показываем наравне с прочими: `0` файлов, `0Кб`, метки нет.
Именно пустая и нужна, когда копируешь новое, — прятать её нельзя.

Страница — те же двадцать строк. Отдельных клавиш для листания нет: курсор
ходит по странице стрелками, а на краю подтягивается следующая или предыдущая.
Открывается список на той дискете, которая назначена сейчас.

## Что берём готовым

| что нужно | откуда |
|---|---|
| ждать клавишу | `0D44` |
| разобрать клавишу по своей таблице | `0562`, таблица как у архива по `2BB5` |
| ввод строки для метки | `28D2`: DE -> предел, длина, текст |
| выход с перерисовкой панели | `2DC3` — уже наша правка |
| счёт файлов и занятых блоков | `count` из `tools/hdir-code.inc` |
| чтение и запись сектора метки | `readlab` из `co-src/hdinfo.asm`, `dolabel` из HDIR |
| назначить дискету на диск | `docmd` из `co-src/hddsel.asm` — команда ОС «9» |
| запомнить выбор | `prmsave` оттуда же, файл `C:CO.HDD` |

Цикл списка целиком повторяет архивный:

```
loop:   CALL показать строку под курсором
        CALL 0D44                       ; ждать клавишу
        LXI  H,таблица
        CALL 0562
        JMP  loop
```

Состояние — три байта, как у архива (`A93C` всего, `A93D` верх окна, `A93E`
курсор): всего дискет, номер первой на странице, курсор.

## Винчестер читаем портами, а не через БСВВ

Это главное, что отличает список от всего, что сборка делала до сих пор.
Дисковый вызов БСВВ читает по *диску* — A: или B:, — а диск указывает на ту
дискету, которая ему назначена. Дискету, которая не назначена никуда, через
БСВВ не прочитать вовсе, а назначать каждую по очереди нельзя: это и медленно,
и сбивает текущий выбор.

Поэтому читаем сами, портами `50h..58h`, в том же порядке, что и БСВВ. Готовый
и проверенный на живом винчестере код есть в `tools/hdir-code.inc` — `rdsec`,
`wrsec`, `rwcmd`, `ready`; HDIR по той же причине не просит у системы ничего.

Раскладка винчестера (оттуда же):

```
сектор 0              заголовок: физика диска и число дискет (по 84h)
секторы 2..81         системная область, общая на все дискеты
дискета N, сектор 0   622h*(N-1) + 2
   +80                каталог: 128 записей по 32 байта, 8 секторов
   +1568              сектор метки: подпись 'HDLB' и 32 знака
```

Дискета — 390 блоков по 2 Кб, то есть 780 Кб. Занято — число ненулевых ссылок
на блоки во всех записях каталога: блок в CP/M принадлежит ровно одному файлу.
Файлов — записей с нулевым экстентом.

Страница в двадцать дискет обходится в 20 × (8 + 1) = 180 секторов, 90 Кб.
Внутри страницы курсор ходит даром, платим только на границе.

## Где что лежит

- **код** — в окне ОЗУ, `A200-A447`, 584 байта. Выведено перебором по листингу
  (`tools/winholes.py`): дыра `A200-A7FF`, накладки в ней занимают `A448-A61B`,
  надпись в рамке — `A660-A7EB`;
- **каталог дискеты на время счёта** — 4 Кб в буфере копирования, с `6100`;
  туда же читает свой каталог архив, и одновременно они не живут;
- **страница списка** — двадцать строк, там же в буфере копирования.

Выход из списка обязан перерисовывать панель: её картинку CO держит в буфере
копирования, а мы его затрём. Тот же случай, что мы уже чинили у архива
правкой по `2DC3`.

## Порядок работы

1. Список открывается и показывает номера и метки; стрелки, страницы, АР2.
2. ВК назначает дискету и перечитывает панель.
3. Файлы и занятое место в строке.
4. Метка по «6».
5. Справка: `docs/co-help.md`, про «СС»-«7» и «УС»-«СС»-«7».

## Что проверить на стенде

- **Какой бит в `A801` означает «УС»**. Что бит `20h` — это «СС», видно по
  обработчику кода `20h` (`036D`): при взведённом бите это «СС»-«0» и гашение
  монитора, при чистом — обычный «0». Про `40h` сказано в справке CO
  («УС»-«4»), но снять надо своими глазами — слежением за `A801`, тем же
  способом, каким снимали коды клавиш.
- **Доходит ли «УС»-«СС»-«7» до CO вообще.** Если нет — ввод номера придётся
  оставить внутри списка, отдельной клавишей.
- **Сколько на самом деле длится чтение страницы.** v06x в клоне винчестер
  эмулирует (порты `50h..58h`, ключ `--hdd`), но скорость там не настоящая.
